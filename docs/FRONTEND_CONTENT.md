# محتوای سایت: راهنمای فرانت (kiva-fe و پنل)

> بک‌اند: برنچ `content-basics`، فاز ۵ ِ `COMPLETION_ROADMAP.md` (گام‌های ۵.۰ تا ۵.۵)، ۲۹ مهر ۱۴۰۵. مرجع دقیق شکل درخواست‌ها و پاسخ‌ها کانترکت `api/kiva-openapi.yml` (نسخه‌ی 1.12.0) است؛ بخش ۱۰.۵ ِ نقشه‌ی راه هر تغییر کانترکت این فاز رو فهرست کرده، و تصمیم‌های ۱ تا ۲۵ ِ بخش ۱۰.۲ دلیل هر قانون رو.
> این فایل می‌گه چی از `GET /config` میاد و دیگه نباید تو `kiva.js` ثابت بمونه، صفحه‌های ثابت و سؤالات متداول و نوار اطلاعیه چطور خونده و (در پنل) نوشته می‌شن، و کجاها راحت می‌شه اشتباه کرد.

## خلاصه

- **همه‌ی عددها و متن‌های ثابت `kiva.js` از `GET /config` میان.** یه بار موقع بالا اومدن اپ بخون و نگه دار؛ سرور خودش با `ETag` و `max-age=300` کش می‌کنه.
- `GET /pages/{slug}` و `GET /faq` هم عمومی و کش‌شونده‌ان (`ETag`، `304`). صفحه‌ی ننوشته ← `404`: صفحه‌ی «در حال تکمیل» نساز، لینکش رو نشون نده.
- در پنل: صفحه‌ها، سؤالات و اطلاعیه‌ها با `ADMIN` یا `CONTENT_EDITOR`. هر سه **کل** چیز رو با `PUT` جایگزین می‌کنن (صفحه کل صفحه؛ سؤالات کل درخت؛ اطلاعیه‌ها کل لیست)؛ پس فرم رو همیشه از `GET` ِ پنل پر کن، نه از نسخه‌ی عمومی.
- HTML ِ محتوا (`HtmlString`) پاک‌سازی‌شده‌ست و می‌شه با `innerHTML` گذاشت. هایلایت سؤالات هم امنه (پایین‌تر).

## ۱. `GET /config`: چی جای چی

| تو `kiva.js` | از `/config` |
|---|---|
| `SHIPPING` (اسم، توضیح، قیمت) | `shipping.methods` (فقط فعال‌ها، به ترتیب تنظیمات؛ `description` آماده) |
| `FREE_POST` | `shipping.freeShippingThreshold` و `shipping.freeShippingMethods` |
| `MSGR` (لینک شبکه‌ها) | `social` (لینک‌ها)؛ پیام‌رسان‌های عکس قبل از ارسال: `preShipmentPhoto.channels` |
| پیام‌های چرخشی بالای سایت | `announcements` (فقط اون‌هایی که الان وقتشونه، به ترتیب) |
| تلفن، ایمیل، ساعت پاسخگویی فوتر | `support.phoneDisplay` (آماده‌ی نمایش، ارقام فارسی)، `support.phone` (برای `tel:`)، `support.email`، `support.hours`، `support.isOpenNow` |
| شعار، درباره‌ی فوتر، لوگوها | `brand` (آدرس لوگوها کامل) |
| «رزرو ۴ روزه»، «۷ روز بازگشت»، `perks` ِ صفحه‌ی محصول | `reservation.holdDays`، `returns.windowDays`، `productPerks` (عددهای داخل متن‌ها از تنظیمات پر شدن) |
| ستون «راهنمای خرید» ِ فوتر | `footerLinks` |
| نشان اینماد و ساماندهی | `trustBadges` (فعلاً خالی؛ تا کدشون نیومده هیچ نشانی نشون نده) |
| ۵ رقم کد ورود، ۱۲۰ ثانیه تا ارسال دوباره | `auth.otpLength`، `auth.resendCooldownSeconds` |
| آستانه‌ی «موجودی کم» | `inventory.lowStockThreshold` (کارت‌ها خودشون `stock.status` دارن؛ این فقط برای متنه) |
| درگاه‌ها | `paymentGateways` (همون لیست صفحه‌ی تسویه، با `available` و `isDefault`) |
| پرچم‌ها | `features` |

- `support.phone`، `phoneDisplay` و `email` می‌تونن `null` باشن (هنوز ثبت نشدن): اون بخش رو نشون نده.
- `support.isOpenNow` با ساعت تهران حساب می‌شه، ولی پاسخ تا ۵ دقیقه کشه، پس ممکنه چند دقیقه دیر عوض بشه. ردیف «فقط پیام‌رسان» (مثلاً جمعه) هیچ‌وقت «الان پاسخگوییم» نمی‌ده.
- `preShipmentPhoto.enabled` و `required` همیشه `true` ـن؛ شرط نذار.
- ترتیب `nonShippingWeekdays` هفته‌ی ایرانیه (شنبه اول).

**دیگه نباید تو `kiva.js` ثابت بمونه:** `SHIPPING`، `FREE_POST`، `MSGR`، پیام‌های نوار بالا، تلفن و ایمیل و ساعت پشتیبانی، شعار و متن «درباره»، `perks`، لینک‌های «راهنمای خرید»، عدد «۴ روز» و «۷ روز» در هر متنی. `CODES` (کدهای تخفیف) هم از قبل از سرور می‌اومد. داده‌ی نمونه‌ی محصول‌ها و دسته‌ها (`PRODUCTS`، `CATS`، `COLORS`) از قبل با API ـه.

## ۲. صفحه‌های ثابت

```js
GET /pages/terms                 200 StaticPage  |  404 (ننوشته)
GET /admin/pages                 [AdminStaticPageSummary]   (بدون محتوا، به ترتیب slug)
PUT /admin/pages/terms           { "title": "...", "content": "<p>…</p>", "seo": { "title": null, "description": null, "noIndex": false } }
200 StaticPage   (ساخته یا ویرایش شده؛ همون چیزی که GET /pages/terms می‌ده)
```

- صفحه‌های لازم برای انتشار: `terms`، `privacy`، `returns`، `about`. هیچ‌کدوم از پیش ساخته نشدن.
- `slug` ِ بدنه یا نیاد یا همون مسیر باشه (`400 SLUG_IMMUTABLE`)؛ صفحه هیچ‌وقت تغییر اسم نمی‌ده و حذف نمی‌شه.
- `content` بعد از پاک‌سازی ۱ تا ۵۰٬۰۰۰ نویسه؛ لینک‌ها فقط `https://…`، `/مسیر` و `#جا` می‌مونن (پایین‌تر). `title` ۱ تا ۱۲۰.
- `seo.canonicalUrl` همیشه `{سایت}/pages/{slug}` و `seo.title` ِ خالی یعنی «عنوان | کیوا».

## ۳. سؤالات متداول

```js
GET /faq?q=رزرو                  FaqResponse   (کش‌شونده)
GET /admin/faq/groups            [FaqGroup]    (بدون کش، بدون هایلایت)
PUT /admin/faq/groups            [FaqGroupInput]  ← 200 [FaqGroup]
```

- `FaqGroup.id` همون anchor ِ لینکه (`/faq#reserve`). ترتیب = ترتیب آرایه‌ها؛ `sortOrder` فقط جای هر چیزه.
- `PUT` **کل درخت** رو جایگزین می‌کنه: گروه یا سؤالی که نفرستی حذف می‌شه. سؤال با `id` همون سؤاله (حتی اگه به گروه دیگه بره)، بی `id` سؤال تازه. خطاها با مسیر میان (`2.questions.0.answer`)؛ «بیشتر از ۲۰ گروه» روی `groups`.
- **جستجو:** با `q` فقط گروه‌ها و سؤال‌های جور میان، `totalMatches` تعداد سؤال‌های جوره. «ي/ی»، «ك/ک»، رقم فارسی و لاتین و حروف بزرگ و کوچک فرقی نمی‌کنن. بی نتیجه: `groups: []` و `emptyMessage` (نشونش بده). بیشتر از ۱۰۰ حرف ← `400` روی `q`.
- **هایلایت امنه:** `questionHighlighted` متن سؤال escape‌شده با `<mark>` ـه و `answerHighlighted` همون HTML ِ جواب با `<mark>` فقط داخل متن. هر دو رو با `innerHTML` بذار؛ **خودت روی `question` ِ خام `<mark>` نذار** (سؤال متن ساده‌ست و ممکنه `<` داشته باشه).

## ۴. نوار اطلاعیه

```js
GET /admin/announcements         [Announcement]   (همه، زمان‌بندی‌شده و تمام‌شده هم)
PUT /admin/announcements         [AnnouncementInput]  ← 200 [Announcement]
```

- حداکثر ۱۰ پیام (`400 TOO_MANY_ITEMS` روی `announcements`). `text` ۱ تا ۲۰۰؛ `url` یا `null` یا `https://…` یا `/مسیر` (`URL_INVALID`)؛ `endsAt` بعد از `startsAt`.
- مثل سؤالات: با `id` همون پیام، بی `id` تازه، نفرستاده حذف. سایت فقط اونایی رو می‌بینه که الان وقتشونه (`GET /config`)، پس بعد از ذخیره تا ۵ دقیقه ممکنه سایت هنوز نسخه‌ی قبلی رو نشون بده.

## ۵. لینک‌ها در HTML

پاک‌سازی سرور (صفحه‌ها، جواب سؤالات، توضیح محصول) فقط این `href`ها رو نگه می‌داره: `https://…` و `http://…`، مسیر سایت با یه `/` (`/faq#reserve`، `/products?onSale=true`)، و `#جا`. `//دامنه`، `/\دامنه`، `javascript:`، `mailto:` و مسیر بی `/` (`faq`) `href` ـشون رو از دست می‌دن و فقط متنشون می‌مونه. ویرایشگر پنل بهتره همون موقع نوشتن هشدار بده.

## اشتباه‌های رایج

- ثابت نگه داشتن `SHIPPING` یا `FREE_POST` و نشون دادن عددی که سبد قبول نداره.
- پر کردن فرم پنل از `GET /config` یا `GET /faq` (فقط چیزهای در حال نمایش یا جورشده رو دارن) و پاک شدن بقیه با `PUT`.
- گذاشتن `<mark>` روی `question` ِ خام به‌جای `questionHighlighted`.
- ساختن صفحه‌ی خالی برای `terms` وقتی `404` اومده.
- انتظار اینکه بعد از ذخیره‌ی اطلاعیه، سایت همون لحظه عوض بشه (کش ۵ دقیقه‌ای).
