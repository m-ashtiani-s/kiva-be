# «موجود شد خبرم کن» و «سؤال داری؟»: راهنمای فرانت (kiva-fe و پنل)

> بک‌اند: برنچ `stock-alerts`، فاز ۱۰ ِ `COMPLETION_ROADMAP.md` (گام‌های ۱۰.۰ تا ۱۰.۴)، ۱ آبان ۱۴۰۵. مرجع دقیق شکل درخواست‌ها و پاسخ‌ها کانترکت `api/kiva-openapi.yml` (نسخه‌ی 1.16.0) است؛ بخش ۱۵.۸ ِ نقشه‌ی راه تغییرات کانترکت این فاز رو فهرست کرده، و تصمیم‌های بخش ۱۵.۲ دلیل هر قانون رو.

## خلاصه

- «موجود شد خبرم کن» **فقط با ورود**. دکمه رو برای مهمان هم نشون بده، ولی کلیکش ← صفحه‌ی ورود و بعد برگشت به همین محصول (و همین رنگ). فیلد `phone` دیگه نیست: پیامک همیشه به **موبایل حساب** می‌ره و `phoneMasked` ِ پاسخ همونه («به ۰۹۱۲***۶۷۸۹ پیامک می‌دیم»).
- اشتراک یا برای **یه رنگ** (`variantId`) ـه یا برای **هر رنگی** از محصول (بدون `variantId`).
- پیامک رو یه کار زمان‌بندی‌شده **تا ۵ دقیقه بعد از موجود شدن** می‌فرسته، از هر راهی که موجود شده باشه؛ **نه بین ۲۲ تا ۸ صبح تهران** (اون موقع صبح می‌ره). هر اشتراک فقط یه بار پیامک می‌گیره و بعدش `NOTIFIED` می‌شه.
- «سؤال داری؟» عمومیه و لینک هر پیام‌رسان رو با متن آماده از سرور می‌گیره. **پیش‌پر شدن متن دست پیام‌رسانه**، پس `prefilledText` رو با دکمه‌ی «کپی متن» هم نشون بده.

## ۱. دکمه‌ی «موجود شد خبرم کن» در صفحه‌ی محصول

```js
GET /products/{idOrSlug}
  stockAlert: { subscribed, alertId }                 // اشتراک «هر رنگی» ِ همین کاربر
  variants[].stockAlertSubscribed: true | false       // اشتراک همین رنگ
```

- مهمان همیشه `stockAlert = { subscribed: false, alertId: null }` و `stockAlertSubscribed = false`.
- رنگ ناموجود (`stock.status = OUT_OF_STOCK`) ← به‌جای «افزودن به سبد»، «موجود شد خبرم کن». اگه `stockAlertSubscribed` روشنه، «بهت خبر می‌دیم ✓» با دکمه‌ی لغو.
- وقتی همه‌ی رنگ‌ها ناموجودن، می‌تونی «هر رنگی موجود شد خبرم کن» هم پیشنهاد بدی (با `stockAlert`).
- توکن منقضی روی صفحه‌ی محصول `401` می‌گیره، نه پاسخ مهمان: اول توکن رو تازه کن.

## ۲. ثبت

```js
POST /products/{productId}/stock-alerts     { "variantId": 501 }    // بدنه اختیاری: {} یا هیچ ← «هر رنگی»
201 StockAlert { id, product, variantId, color, channel: "SMS", phoneMasked, status: "ACTIVE", createdAt, notifiedAt: null, message }
```

| جواب | کِی | چی نشون بدی |
|---|---|---|
| `401` | مهمان | صفحه‌ی ورود |
| `404 PRODUCT_NOT_FOUND` | محصول از سایت برداشته شده | صفحه رو تازه کن |
| `400 VARIANT_NOT_FOUND` روی `variantId` | رنگ مال این محصول نیست یا غیرفعال شده | صفحه رو تازه کن |
| `409 STOCK_ALERT_EXISTS` | همین الان اشتراک فعال داری | مثل موفقیت رفتار کن («بهت خبر می‌دیم») |
| `422 PRODUCT_IN_STOCK` | اون رنگ همین الان موجوده؛ برای «هر رنگی»، یه رنگی موجوده و کلیدهاش در `meta.inStockColorKeys` | رنگ موجود رو انتخاب کن و «افزودن به سبد» رو نشون بده |
| `422 STOCK_ALERT_LIMIT_REACHED` | ۳۰ اشتراک فعال داری (`meta.limit`) | «اشتراک‌های من» رو پیشنهاد بده |
| `429 RATE_LIMITED` | بیشتر از ۱۰ ثبت در یه ساعت؛ هدر `Retry-After` | پیام خطا |

متن فارسی هر خطا در `message` ِ پاسخ خطا آماده‌ست. «هر رنگی» و «یه رنگ خاص» از یه محصول با هم مجازن.

## ۳. «اشتراک‌های من» و لغو

```js
GET    /me/stock-alerts                 [StockAlert]       // نه صفحه‌بندی؛ حداکثر ۱۰۰
DELETE /me/stock-alerts/{alertId}       204
```

- فعال‌ها و «خبر داده‌شده»های ۹۰ روز اخیر، تازه‌ترین ثبت اول. لغوشده‌ها نمیان.
- `message` برای هر وضعیت آماده‌ست: «هر وقت موجود شد، بهت پیامک می‌دیم» / «موجود شد و بهت خبر دادیم». برای `NOTIFIED` دکمه‌ی «برو به محصول» (`product.slug` و `product.colorKey`).
- `color = null` یعنی «هر رنگی».
- لغو اشتراکی که دیگه فعال نیست هم `204` ـه (دکمه رو بدون خطا بردار). اشتراک کس دیگه یا ناموجود ← `404 STOCK_ALERT_NOT_FOUND`.

## ۴. «سؤال داری؟ عکس یا ویدیوی بیشتر بخواه»

```js
GET /products/{productId}/inquiry?color=lilac          // عمومی؛ color اختیاری
200 { productCode, productName, colorName, prefilledText, channels: [{ channel, name, url, handle, responseHours }] }
```

- `color` همون رنگیه که کاربر روی صفحه می‌بینه؛ نفرستی ← رنگ پیش‌فرض. رنگی که محصول نداره ← `400 COLOR_NOT_FOUND` روی `color`؛ محصول منتشرنشده ← `404`.
- `channels` فقط روبیکا، تلگرام و بله، به ترتیب تنظیمات (اینستاگرام لینک متن‌دار نداره؛ لینکش در `/config` → `social` هست). لیست خالی ← فقط متن و دکمه‌ی کپی.
- هر `url` آماده‌ی باز شدنه (`…?text=` یا `…&text=`، متن کدشده): مستقیم در `href` بذار، خودت چیزی بهش اضافه نکن.
- `handle` (مثل `@kiva_shop`) و `responseHours` («پاسخگویی ۹ تا ۲۱») ممکنه `null` باشن.
- پاسخ کش نمی‌شه؛ با هر باز شدن پنجره یا عوض شدن رنگ دوباره بخون.

## ۵. پنل: صف «موجود شد خبرم کن»

```js
GET /admin/stock-alerts?productId=12&inStock=false&page=1&size=20      // ADMIN، CATALOG_MANAGER
200 { items: [AdminStockAlertGroup], meta }
```

- هر ردیف: `product`، `variantId`/`color`/`sku` (هر سه `null` = «هر رنگی»)، `waitingCount`، `oldestAt`، `availableQuantity` (موجودی قابل فروش دقیق؛ برای «هر رنگی» جمع رنگ‌های فعال)، `stockStatus`.
- ترتیب ثابت: بیشترین منتظر اول، بعد قدیمی‌ترین. پارامتر `sort` نداره.
- `inStock=false` همون «باید تولید/سفارش بدیم»ه؛ ردیفی با `availableQuantity > 0` یعنی پیامکش تا چند دقیقه‌ی دیگه می‌ره و از صف خارج می‌شه.
- **هیچ شماره‌ای در صف نیست**؛ پنل فقط می‌شمره.
- در فرم محصول، `variants[].stockAlertSubscribers` تعداد منتظرهای همون رنگه (بدون «هر رنگی»).
- خطاها: `inStock` جز `true`/`false` ← `400 BOOLEAN_INVALID`؛ `productId` بدشکل ← `400 PRODUCT_ID_INVALID`؛ `OPERATOR` و `SUPPORT` ← `403`.
