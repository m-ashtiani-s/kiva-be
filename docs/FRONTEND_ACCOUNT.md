# حذف حساب و رسید خرید: راهنمای فرانت (kiva-fe و پنل)

> بک‌اند: برنچ `account-closure`، فاز ۱۴ ِ `COMPLETION_ROADMAP.md` (گام‌های ۱۴.۰ تا ۱۴.۴)، ۲ آبان ۱۴۰۵. مرجع دقیق کانترکت `api/kiva-openapi.yml` (نسخه‌ی 1.20.0) است؛ بخش ۱۹.۷ ِ نقشه‌ی راه تغییرات کانترکت و بخش ۱۹.۲ دلیل هر قانون.

## خلاصه

- حذف حساب دو مرحله‌ست: `POST /me/deletion/request` (کد به موبایل خود حساب) و بعد `DELETE /me` با همون کد. هر دو ورود لازم دارن.
- مانع‌ها **قبل** از پیامک چک می‌شن: سفارش جاری ← `422 ACCOUNT_HAS_ACTIVE_ORDERS` با `meta.orderCodes`؛ حساب کارمند ← `422 STAFF_ACCOUNT_CANNOT_BE_DELETED`. در این دو حالت پیامکی نمی‌ره.
- بعد از `204` ِ `DELETE /me`: همه‌ی نشست‌ها باطلن، کوکی `kiva_rt` پاک شده، و **همون توکن دسترسی هم دیگه کار نمی‌کنه** (`401`). حالت ورود رو پاک کن و کاربر رو به صفحه‌ی اصلی ببر.
- رسید خرید PDF: `GET /me/orders/{orderCode}/invoice` برای سفارشی که یه بار پرداخت شده (لغوشده و مرجوعی‌شده هم). `OrderDetail.invoiceUrl` همین آدرسه، یا `null` اگه هنوز پرداخت نشده؛ دکمه‌ی «دانلود رسید» رو فقط وقتی `invoiceUrl` هست نشون بده.

## ۱. حذف حساب (kiva-fe، صفحه‌ی «حساب من» › «حذف حساب»)

### مرحله‌ی ۱: گرفتن کد

```js
POST /me/deletion/request        (بدون بدنه، با Authorization)
200 { phone: "09121234567", codeLength: 5, expiresInSeconds: 300, resendAvailableInSeconds: 120 }
```

| پاسخ | یعنی | چی نشون بدی |
|---|---|---|
| `200` | کد به `phone` رفت | فرم کد ۵ رقمی، تایمر ارسال دوباره از `resendAvailableInSeconds` |
| `422 ACCOUNT_HAS_ACTIVE_ORDERS` | سفارش جاری داره؛ کدی نرفت | متن خطا و فهرست `meta.orderCodes` با لینک به هر سفارش (`/account/orders/{code}`) |
| `422 STAFF_ACCOUNT_CANNOT_BE_DELETED` | حساب نقش پنل داره | متن خطا؛ ادمین باید اول نقش‌ها رو برداره |
| `429 OTP_RESEND_TOO_SOON` / `RATE_LIMITED` / … | همون سقف‌های کد ورود | زمان انتظار از `meta.retryAfterSeconds` (و هدر `Retry-After`) |
| `401` | توکن نیست یا حساب دیگه نیست | مثل هر `401` |

«سفارش جاری» یعنی سفارشی در `PENDING_PAYMENT`، `PAYMENT_FAILED`، `RESERVED`، `PROCESSING`، `PHOTO_SENT`، `CHANGE_REQUESTED`، `SHIPPED`، `RETURN_REQUESTED` یا `RETURNED`، یا سفارشی که مانده‌ی پرداخت‌نشده داره، یا استردادی که هنوز `PENDING`/`PROCESSING` ـه. سفارش تحویل‌شده، لغوشده (بی استرداد باز)، منقضی یا برگشت‌خورده مانع نیست.

### مرحله‌ی ۲: حذف

```js
DELETE /me   { otpCode: "48213", reason?: "دیگه کیف لازم ندارم" }
204          Set-Cookie: kiva_rt=; Max-Age=0; Path=/api/v1/auth; Secure; HttpOnly; SameSite=Strict
```

- `otpCode` همون کد مرحله‌ی ۱ (ارقام فارسی هم قبوله). **کد ورود این‌جا قبول نمی‌شه** و کد حذف هم برای ورود.
- `reason` اختیاری، حداکثر ۳۰۰ حرف. بی هیچ شناسه‌ای ذخیره می‌شه (فقط متن و تاریخ)؛ می‌تونی بگی «دلیلت رو بی‌نام نگه می‌داریم».
- `fetch` با `credentials: "include"` بفرست تا مرورگر `Set-Cookie` ِ پاک‌کننده رو بپذیره.

| پاسخ | یعنی | چی نشون بدی |
|---|---|---|
| `204` | حساب حذف شد | پیام «حسابت حذف شد»، پاک کردن توکن از حافظه، رفتن به خانه |
| `400 VALIDATION_ERROR` | `otpCode` بدشکل (`OTP_CODE_FORMAT_INVALID`) یا `reason` بلند (`DELETION_REASON_TOO_LONG`) | خطا زیر فیلد خودش |
| `422 OTP_INVALID` | کد غلط؛ `meta.attemptsLeft` تلاش مونده | «کد درست نیست، N بار دیگه» |
| `422 OTP_EXPIRED` | کدی نیست یا گذشته | دکمه‌ی «ارسال دوباره‌ی کد» |
| `422 OTP_TOO_MANY_ATTEMPTS` | پنج بار غلط | کد تازه لازمه |
| `422 ACCOUNT_HAS_ACTIVE_ORDERS` / `STAFF_ACCOUNT_CANNOT_BE_DELETED` | بین دو مرحله سفارش تازه‌ای ثبت شد یا نقش گرفت | مثل مرحله‌ی ۱؛ **کد مصرف نشده** و بعد از رفع مانع هنوز معتبره (تا ۵ دقیقه) |
| `429 RATE_LIMITED` | ده کد غلط امروز برای این موبایل | زمان انتظار از `meta.retryAfterSeconds` |

### متن صفحه (پیشنهاد)

قبل از دکمه‌ی نهایی، روشن بگو چی می‌شه:

> با حذف حساب، اسم، موبایل، ایمیل، آدرس‌ها، سبد، علاقه‌مندی‌ها، «موجود شد خبرم کن»ها، پیام‌های فرم تماس و عضویت خبرنامه‌ت پاک می‌شن و از همه‌ی دستگاه‌ها خارج می‌شی. سفارش‌های قبلی برای حسابداری بی‌نام می‌مونن (فقط استان و شهر)، و نظرهات با اسم «کاربر کیوا» می‌مونن. این کار برگشت نداره؛ اگه دوباره با همین شماره وارد بشی، یه حساب تازه‌ی خالی ساخته می‌شه.

## ۲. رسید خرید PDF (kiva-fe، صفحه‌ی سفارش)

```js
GET /me/orders/{orderCode}/invoice        (با Authorization)
200  Content-Type: application/pdf
     Content-Disposition: attachment; filename="kiva-KV-215566.pdf"
     Cache-Control: private, no-store
```

- از `invoiceUrl` ِ خود `OrderDetail` استفاده کن (`/api/v1/me/orders/KV-215566/invoice`)، نه ساختن آدرس با دست.
- چون توکن در هدر `Authorization` ـه، لینک ساده (`<a href>`) کار نمی‌کنه: با `fetch` بگیر، `blob()` کن، و با `URL.createObjectURL` دانلود کن. اسم فایل رو از `Content-Disposition` بخون (CORS این هدر رو expose می‌کنه):

```js
const r = await fetch(invoiceUrl, { headers: { Authorization: `Bearer ${token}` } })
if (!r.ok) throw await r.json()                       // 404 ORDER_NOT_FOUND، 422 INVOICE_NOT_AVAILABLE
const name = /filename="([^"]+)"/.exec(r.headers.get('Content-Disposition'))?.[1] ?? 'kiva.pdf'
const url = URL.createObjectURL(await r.blob())
Object.assign(document.createElement('a'), { href: url, download: name }).click()
URL.revokeObjectURL(url)
```

| پاسخ | یعنی |
|---|---|
| `200` | فایل PDF ِ یه صفحه‌ی A4 |
| `422 INVOICE_NOT_AVAILABLE` | سفارش هنوز پرداخت نشده (اگه `invoiceUrl` رو چک کنی پیش نمیاد) |
| `404 ORDER_NOT_FOUND` | سفارش نیست یا مال کس دیگه‌ست |

- محتوا: «رسید خرید» (نه فاکتور رسمی مالیاتی)، فروشگاه، کد سفارش، تاریخ پرداخت (شمسی، وقت تهران)، خریدار و نشانی سفارش، ردیف‌های **فعلی** ِ سفارش (بعد از درخواست تغییر)، جمع‌ها مثل `OrderDetail.totals`، روش ارسال و کد رهگیری. سفارش لغوشده یه نوار قرمز «لغو شده» بالای صفحه داره.
- `no-store`: هر بار از سرور بگیر؛ کش نکن.

## ۳. پنل

- **مشتری‌ها:** حساب حذف‌شده در `GET /admin/customers` نمیاد (نه با جستجوی موبایل قبلیش)، و `GET /admin/customers/{id}` و `PUT /admin/customers/{id}/roles` برای اون `404` می‌دن. `GET /admin/customers/{id}` برای حساب حذف‌شده کد `CUSTOMER_DELETED` می‌ده و برای شناسه‌ای که اصلاً نیست `NOT_FOUND` (کانترکت 1.22.0): اولی رو «این حساب حذف شده» نشون بده، نه «پیدا نشد». شناسه‌ی این حساب هنوز در سفارش‌ها، مرجوعی‌ها و نظرهاش هست، پس لینک بهش ممکنه.
- **سفارش بی‌نام** (حساب حذف‌شده): در `AdminOrder`، `customer.fullName` و `customer.phone` `null`ـن؛ «حساب حذف‌شده» نشون بده. `address` فقط `provinceName` و `cityName` داره (بقیه `null`) و `fullText` فقط «استان، شهر» ـه. در لیست سفارش‌ها `customerName` و `customerPhone` هم `null` می‌شن. `preShipmentMediaDetail.phone` و `username` و `note` هم `null`ـن (کانال می‌مونه). مبلغ‌ها، ردیف‌ها، کد رهگیری و تاریخ‌ها سر جاشونن.
- **مرجوعی‌ها:** `customer.phone` ِ مرجوعی ِ حساب حذف‌شده `null` ـه.
- **کارمند:** کارمندی که می‌خواد حسابش رو حذف کنه، اول باید ادمین همه‌ی نقش‌های پنلش رو برداره.

## ۴. متن «حذف حساب» برای صفحه‌ی حریم خصوصی

برای بخش «حذف حساب» ِ صفحه‌ی ثابت حریم خصوصی (`PUT /admin/pages/{slug}` در پنل). محدودیت تصمیم ۳ ِ فاز ۱۴ (تاریخچه‌ی داخلی سفارش) صادقانه گفته شده؛ اگه متن حقوقی دیگه‌ای خواستی، فقط همین بخش عوض می‌شه (سؤال باز ۱۱).

```html
<h2>حذف حساب</h2>
<p>هر وقت بخوای می‌تونی از «حساب من» › «حذف حساب» حسابت رو حذف کنی. برای اطمینان، یه کد به موبایل خود حساب می‌فرستیم.
تا وقتی سفارشی در راه، پرداخت یا استرداد باز داری، حذف ممکن نیست؛ اول اون کار تموم می‌شه.</p>
<p>با حذف حساب، این‌ها پاک می‌شن: اسم، موبایل، ایمیل، تاریخ تولد و جنسیت؛ آدرس‌ها؛ سبد خرید؛ علاقه‌مندی‌ها و لینک اشتراکشون؛
درخواست‌های «موجود شد خبرم کن»؛ پیام‌هایی که بعد از ورود با فرم تماس فرستادی؛ و عضویت خبرنامه با ایمیل حساب. از همه‌ی دستگاه‌ها هم خارج می‌شی.</p>
<p>سفارش‌های قبلی و مرجوعی‌ها و استردادها سند مالی‌ان و می‌مونن، ولی بی‌نام: اسم و موبایل گیرنده، نشانی، کد پستی، پیام‌رسان،
توضیح سفارش و پیام هدیه پاک می‌شن و فقط استان و شهر، مبلغ‌ها و کالاها می‌مونن. نظرهایی که نوشتی با اسم «کاربر کیوا» می‌مونن.</p>
<p>تاریخچه‌ی داخلی ِ ثبت سفارش‌ها (که برای درستی حساب‌ها فقط اضافه می‌شه و عوض نمی‌شه) نشانی ِ زمان ثبت رو نگه می‌داره؛
این داده هیچ‌جا نمایش داده نمی‌شه و از هیچ راهی بیرون نمی‌ره. سوابق امنیتی (مثل ورودها) هم برای جلوگیری از سوءاستفاده می‌مونن.</p>
<p>اگه بعداً با همون شماره وارد بشی، یه حساب تازه و خالی ساخته می‌شه که به سفارش‌های قبلی ربطی نداره.</p>
```
